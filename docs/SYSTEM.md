# The Mei system ROM

The console's "operating system" is an ordinary Mei program, `system/system.akr`, built to
`build/system.mei`. It runs on the emulated hardware like any cart. At power-on the platform
loads it instead of a cart. It plays a boot animation, then shows a small shell: a cart
browser, settings, a controller test, a sound test and system information. Two extra I/O
registers and a catalogue that the platform writes into ROM let it launch carts.

## Size

The system ROM must be at most `0x1F0000` bytes (1,984 KB). The last 64 KB of the ROM
window, from `0x3F0000`, holds the catalogue.

## Catalogue (`0x3F0000`, read-only)

The platform appends this after loading the system ROM. All values are little-endian.

| Offset | Size | Field |
|---|---|---|
| +0 | 4 | `"CATL"` |
| +4 | 4 | number of carts (at most 512) |
| +8 | 4 | autoboot: index of a cart to launch after the boot animation, or `0xFFFFFFFF` |
| +12 | 4 | flags: bit 0 skip the boot animation; bit 1 returning from a cart (go straight to the shell) |
| +16 | 16 | platform name, NUL-padded (`"desktop"`, `"web"`) |
| +32 | 64 × n | entries |

Each entry: bytes 0–31 the title (NUL-padded, from the cart's `MEI1` header, else the file
name), bytes 32–35 the cart size in bytes, bytes 36–63 zero.

If no catalogue is present (the four bytes at `0x3F0000` are not `"CATL"`), the system
ROM behaves as if there are zero carts and no flags.

## Registers

| Address | Name | Access | Purpose |
|---|---|---|---|
| `0xFF0310` | `SYS_LAUNCH` | Write | Launch catalogue entry *n*. The platform loads that cart and resets the console after the current tick. |
| `0xFF0314` | `SYS_CONFIG` | Read/write | One settings word. It survives resets and cart changes, and the platform saves it between sessions. |
| `0xFF0318` | `SYS_TIME` | Read | Local time of day: seconds since midnight (0–86,399) |
| `0xFF031C` | `SYS_DATE` | Read | Local date: bits 0–4 day (1–31), 5–8 month (1–12), 9–11 weekday (0 = Sunday), 16–31 year |

`SYS_CONFIG` layout, owned by the system ROM:

| Bits | Meaning |
|---|---|
| 0–3 | boot theme, 0–1 (see below); out-of-range values fall back to 0 |
| 4 | boot animation off |
| 5–31 | reserved for the shell (documented in `system/system.akr`) |

These registers are an extension for the system ROM. Ordinary carts have no reason to
use `SYS_LAUNCH` or `SYS_CONFIG`; any cart may read the clock. Like controller input, the
clock is latched at `vsync`, so it changes once per frame and a replay that records it stays
deterministic. The headless runner simulates it (`--time`, `--date`; default 12:00 on
2026-01-01, advancing one second per 60 ticks).

## Returning to the system

The platform's Home action (the **Home/Guide** button on a gamepad, or **F2**) reloads the
system ROM with catalogue flag bit 1 set, so the shell comes back without the boot
animation.

## Boot themes

Each theme lives in `system/boot/<name>.akr` with its assets in `system/boot/<name>/`,
generated by `tools/gen_boot_<name>.py`. All names a theme defines start with its prefix
(`duet_`, `DUET_`, ...) because every file shares one namespace.

| # | Name | Look and sound |
|---|---|---|
| 0 | `duet` (DUET) | A sun-drop and a moon-drop bounce on a clean white stage, spin together and pop into 日 and 月; marimba and celesta answer each other |
| 1 | `eclipse` (ECLIPSE) | Sun and moon approach, play, eclipse and unite into 明; singing bowl, bells, a choir swell |

A theme provides two functions:

```
fn duet_start()                 // once, before the first frame
fn duet_frame(t: s32) -> bool   // every frame from draw(), t = 0, 1, 2, ...; true when finished
```

- `t` counts frames from 0. A theme lasts 4–8 seconds and ends on the **MEI** wordmark
  (with 明 if it fits the look), held for about a second. It returns `true` after its last frame,
  and the shell fades to the menu.
- The shell skips the animation when A or Start is pressed. The theme doesn't handle input.
- Themes draw with the standard library (`cls`, `camera`, `mesh`, sprites, `text`, packets by
  hand) and may set `GPU_CTRL` dither as they like.
- Resources: texture slots 0–11 and 4-bit palettes 0–191 (8-bit palettes 0–11) are free
  for the theme during the boot. Slots 12–14 and palettes 192–254 belong to the shell; slot 15
  and palette 255 are the standard library's font. Audio channels 0–5 belong to the theme,
  and 6–7 to the shell's UI sounds. Stop your channels when you finish.
- Audio is pre-rendered by the theme's Python generator as signed PCM at 22,050 Hz. Budget:
  at most 240 KB of samples per theme. Stereo comes from playing samples on two channels with
  different volumes (for example a left mix and a right mix).
- Each theme also has a preview harness, `system/boot/preview_<name>.akr`, that loops just
  that theme, for development.

## Tools

```bash
./build/meic system/system.akr -o build/system.mei
```

```bash
./build/mei-headless build/system.mei --system-carts build/carts --frames 300 --dump out.ppm --wav out.wav
```

`--system-carts DIR` appends a catalogue of the `.mei` files in `DIR`, and `--wav` records the
console's audio output. `make` builds `build/system.mei`, and `build/mei` with no arguments
boots it.
